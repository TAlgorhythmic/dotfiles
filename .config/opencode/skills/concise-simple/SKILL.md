# Concise & Simple

## Answers

- Keep answers short and concise. Lead with the answer; skip preambles, recaps, and filler.
- Only give longer answers when the topic genuinely needs it, such as complex explanations, trade-offs, or multi-step instructions.

## Code

- Be as little verbose as possible: write the least code that solves the problem clearly.
- Use descriptive names for variables, functions, components, and files so the code explains itself.
- Don't comment already clear code. Comment only non-obvious intent, workarounds, or constraints.
- Create reusable code where possible: extract repeated logic into functions, components, hooks, or modules instead of duplicating it.
- Stay simple. Simplicity is the goal: prefer straightforward solutions over clever ones, and don't add abstractions, layers, or dependencies the task doesn't need.
